#### `--auth-provider-cmd` role assumption is reused across a run

An `--auth-provider-cmd` returning an `awsRole` assumed that role again on every fetch, and each fetch after the first signed the `sts:AssumeRole` request with the session the previous one had produced. AWS rejects that with `AccessDenied` unless the role trusts itself, so runs logged repeated `Failed to assume role` warnings, and a unit whose `iam_role` named the same role failed outright.

Terragrunt now lets the session name be generated when the STS request is made rather than when the auth-provider response is read, so the assumed session is cached and reused for the whole run. A `roleSessionName` set in the auth-provider response is still honoured.
