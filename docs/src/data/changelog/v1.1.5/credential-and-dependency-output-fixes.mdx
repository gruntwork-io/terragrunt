#### IAM role sessions are reused instead of assumed again

Terragrunt asked for credentials a second time in the same run and signed that request with the session from the first one. AWS refuses a role that assumes itself, so the run failed with `AccessDenied`. This hit `run --all plan` with `--json-out-dir`, and any `--auth-provider-cmd` returning an `awsRole`. Terragrunt now keeps the assumed session until five minutes before it expires, one hour by default or whatever `--iam-assume-role-duration` sets. A `roleSessionName` in the auth-provider response still applies.

#### Dependency outputs are read from the right directory

With `TF_DATA_DIR` set to an absolute path, every dependency looked as though it had already been initialized. Terragrunt then read outputs from a cache directory that was never created. `plan` failed with a `chdir` error, and `render` exited 0 while writing empty dependency outputs. The check now looks inside the working directory it is vouching for. A relative `TF_DATA_DIR` that resolves inside that directory still applies.
