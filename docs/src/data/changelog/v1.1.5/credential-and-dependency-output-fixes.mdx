#### Credential and dependency output fixes

Two problems are fixed.

**IAM role sessions are reused instead of re-assumed.** Terragrunt assumes an IAM role once and passes the resulting session to every command it runs. Two paths asked for credentials a second time within one run and signed that request with the session the first assumption had produced, which AWS rejects with `AccessDenied` unless the role's trust policy allows it. `run --all plan` with `--json-out-dir` failed while exporting each unit's plan as JSON, and an `--auth-provider-cmd` returning an `awsRole` re-assumed on every fetch, logging repeated `Failed to assume role` warnings and failing outright when a unit's `iam_role` named that same role. Assumed sessions are now cached in-process until five minutes before they expire, one hour by default or whatever `--iam-assume-role-duration` specifies. If a session cannot be refreshed but has not yet expired, Terragrunt logs a warning and continues with the cached credentials rather than failing the run. A `roleSessionName` set in the auth-provider response is still honoured.

**Dependency outputs resolve correctly with an absolute `TF_DATA_DIR`.** Every dependency looked as though it had already been initialized, because the check tested that shared directory rather than the dependency's own working directory. Terragrunt then read outputs from a cache directory that was never created, so `plan` failed with a `chdir` error and `render` exited successfully while writing empty dependency outputs into the rendered inputs. The check now tests a data directory inside the working directory it vouches for. A relative `TF_DATA_DIR` is still honoured.
