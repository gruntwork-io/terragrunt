#### Encrypted dependency state falls back

With the [`dependency-fetch-output-from-state`](/reference/experiments/active#dependency-fetch-output-from-state) experiment enabled, a dependency whose state is protected by OpenTofu client-side state encryption now falls back to the normal `tofu/terraform output` path instead of resolving to empty outputs.

Terragrunt reads the raw state object through the backend's cloud storage API and holds no key material for it. The encrypted envelope parsed as valid JSON with no `outputs` key, so dependency outputs silently resolved to nothing and the run failed later with an unrelated `Unsupported attribute` error. Terragrunt now recognizes the envelope and retrieves the outputs through OpenTofu, so the outputs are correct and only the speedup is lost.

Setting `--no-dependency-fetch-output-from-state` is no longer necessary for encrypted state.
