#### `base64gzip()` uses the current Go encoder

Go 1.27 changed the compressed output of its gzip encoder. Terragrunt v1.1.5 kept `base64gzip()` on the older output and warned once per run that this was legacy behavior. `base64gzip()` now returns what the Go 1.27 encoder produces.

A resource that compares the encoded value can plan a replacement on the first run after upgrading. An [`aws_instance`](https://search.opentofu.org/provider/opentofu/aws/v6.66.0/docs/resources/instance) with [`user_data_base64`](https://search.opentofu.org/provider/opentofu/aws/v6.66.0/docs/resources/instance#attr-user_data_base64) set from `base64gzip()` and [`user_data_replace_on_change`](https://search.opentofu.org/provider/opentofu/aws/v6.66.0/docs/resources/instance#attr-user_data_replace_on_change) set to `true` is one such resource.

Where the encoded value has to stay stable, call the experimental [`base64gzip_compat()`](/reference/hcl/functions/#base64gzip_compat), which returns the v1.1.3 output permanently. It is behind the `base64gzip-compat` experiment and may be renamed or removed:

```bash
terragrunt run --all --experiment base64gzip-compat -- plan
```

```hcl
inputs = {
  user_data_base64 = base64gzip_compat(file("${get_terragrunt_dir()}/user-data.sh"))
}
```

This completes the [`legacy-base64gzip`](/reference/strict-controls/completed#legacy-base64gzip) strict control.

<WithinGuarantees>
  `base64gzip()` still takes a string and returns valid gzipped base64 content that decompresses to the same value, but the encoded value itself changes. `base64gzip_compat()` keeps the old one.
</WithinGuarantees>
