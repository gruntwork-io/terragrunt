#### `base64gzip()` uses a new encoder

Go 1.27 changed the bytes its gzip encoder produced when compressing content. In Terragrunt v1.1.5 avoided using this encoder by default for users when using the `base64gzip()` function, despite being compiled with Go 1.27. Instead it surfaced a warning about this. Terragrunt now returns the bytes generated by the Go 1.27 gzip encoder directly.

This does not break the guarantess made in [1.0 guarantees](/process/1-0-guarantees). `base64gzip()` still takes a string and returns valid gzipped base64 content, and the bytes decompress to the same original value. This is being called out because a resource that compares the exact content of the encoded value can result in a plan that replaces resources on the first run after upgrading.

An example of this would be an [`aws_instance` resource](https://search.opentofu.org/provider/opentofu/aws/latest/docs/resources/instance) with [`user_data_base64`](https://search.opentofu.org/provider/opentofu/aws/latest/docs/resources/instance#attr-user_data_base64) set to a value generated by `base64gzip()` and the attribute [`user_data_replace_on_change`](https://search.opentofu.org/provider/opentofu/aws/latest/docs/resources/instance#attr-user_data_replace_on_change) set to `true`.

For the sake of backwards compatibility, the experimental [`base64gzip_compat()`](/reference/hcl/functions/#base64gzip_compat) is available to help give users time to address anything undesireable from this change. The function is not guaranteed to remain supported in Terragrunt HCL and may be removed in the future.

```bash
terragrunt run --all --experiment base64gzip-compat -- plan
```

```hcl
inputs = {
  user_data_base64 = base64gzip_compat(file("${get_terragrunt_dir()}/user-data.sh"))
}
```

This completes the [`legacy-base64gzip`](/reference/strict-controls/completed#legacy-base64gzip) strict control.
