#### Read GCS dependency outputs directly under service account impersonation

Direct state reads of dependency outputs now work when the GCS backend impersonates a service account. Units that set `impersonate_service_account`, `GOOGLE_BACKEND_IMPERSONATE_SERVICE_ACCOUNT` or `GOOGLE_IMPERSONATE_SERVICE_ACCOUNT` used to run `tofu`/`terraform` output for every dependency.

Terragrunt resolves the account, its `impersonate_service_account_delegates` and the requested OAuth scope (`devstorage.read_write`) the same way the native GCS backend does, so the state is read with the same identity. Delegates set through environment variables still use the normal method.
