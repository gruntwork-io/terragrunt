#### `hcl validate` reports dependencies on deleted units

A `dependency` block that points at a deleted or moved unit made `run --all` fail, while `find`, `list` and `hcl validate` still passed. `hcl validate` now fails for each enabled `dependency` block whose `config_path` does not point at a unit or stack configuration, so the problem is caught before a run:

```bash
terragrunt hcl validate
```

`hcl validate` does not generate stacks, so a `dependency` block that points at a unit inside a `.terragrunt-stack` directory fails until `terragrunt stack generate` has generated that stack. A `dependency` block that points at the stack directory itself is checked against its `terragrunt.stack.hcl`.

When `run --all` fails because a Git-based filter compares against a reference where the unit still exists, such as `--filter '[main...HEAD]'` after deleting the unit, the new `missing-dependency-config` tip names the deleted unit and points at this check. `find` and `list` behave as before.
