#### Stack commands respect `--discovery-boundary`

The `--discovery-boundary` flag now works with `stack generate`, `stack run`, and `stack output`. Previously these commands scanned the entire working directory for stack files and ignored the boundary. In monorepos with a catalog next to live infrastructure, this caused errors when out-of-scope stacks referenced files that only exist in the live tree.

The boundary, including an inline `(dir)` operand, also applies when a Git expression such as `[main...HEAD]` generates stacks in its comparison worktrees. If any filter has no boundary and `--discovery-boundary` is not set, the walk still covers the whole working directory.

Dependent discovery no longer parses units outside every dependent boundary. For Git expressions, the boundary also limits which changed units Terragrunt discovers in the compared worktrees, so a changed unit outside the boundary is no longer a target. A dependent-side boundary can now be a directory inside the working directory, and the search for dependents starts there. You can run `terragrunt stack run plan --filter '(./live/)...[main...HEAD]'` from the repository root, and Terragrunt skips catalog units outside `./live` that only parse after they are generated into a stack.
