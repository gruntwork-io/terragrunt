#### Faster parsing of shared configuration

Repositories where every unit includes a `root.hcl` that loads shared files with [`read_terragrunt_config`](/reference/hcl/functions#read_terragrunt_config) now parse much faster.

- Each unit used to parse those shared files itself, so a `common.hcl` that runs `yamldecode(file(...))` on a large YAML file decoded it once per unit. Terragrunt now parses each file once per command. A file whose result can differ between units, like one that calls `get_original_terragrunt_dir()` or has `dependency` blocks, is still parsed per unit. The [function reference](/reference/hcl/functions#read_terragrunt_config) lists every case.
- Since v1.1.2, discovery parsed every included configuration twice, once for its feature flag defaults and once to merge it. It parses each include once again.
- Locals and inputs went through a JSON encoding round trip on their way into Terragrunt. Terragrunt now converts them directly.

Timing `find --dependencies` on an Apple M3 Max, over a generated repository whose units read a 48 KB YAML file through `read_terragrunt_config` (median of five runs):

| units | before | after |
| --- | --- | --- |
| 100 | 1.22s | 0.11s |
| 500 | 4.24s | 0.26s |
| 1,000 | 8.47s | 0.45s |
| 5,000 | 39.2s | 2.04s |

Files read with `read_terragrunt_config` no longer see the reading unit's locals and feature flags in their `include` and `feature` blocks.
