#### `run_cmd` results are cached per configured environment and exact arguments

The `run_cmd` cache keyed results on the evaluated file's directory and a space-joined argument list. A command in a file shared via `read_terragrunt_config` replayed the first unit's output for every unit, even when `--auth-provider-cmd` had placed different credentials in each unit's environment. `run_cmd("printf", "%s|", "x y")` also shared an entry with `run_cmd("printf", "%s|", "x", "y")`.

The key now includes the configured environment and the exact argument boundaries. An auth provider that returns new credentials on every call changes that environment between parses, so the command runs again in each phase that parses the file with different credentials. Concurrent calls with the same key run the command once and share its result, success or failure. If that one run fails under `--terragrunt-global-cache`, each waiting unit's error names its own directory next to the one the command ran in. Failures are not stored, so a later call runs the command again.
