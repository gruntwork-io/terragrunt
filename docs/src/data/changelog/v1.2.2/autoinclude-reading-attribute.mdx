#### Autoinclude `reading` attribute for unit read tracking

The `autoinclude` block in `terragrunt.stack.hcl` now accepts a `reading` attribute: a list of file paths that the generated unit reads. Terragrunt writes `mark_as_read()` calls into the generated `terragrunt.autoinclude.hcl` so that `terragrunt find --reading` and `--filter reading=<file>` attribute the reads to the unit instead of the stack.

This solves the case where an autoinclude's `inputs` uses `templatefile()` with a dependency output: the template file read was invisible to affected-unit detection because `templatefile()` resolves at generate time and inputs are not evaluated during discovery.

```hcl
unit "render" {
  source = "../catalog/units/echo"
  path   = "render"

  autoinclude {
    reading = ["${get_terragrunt_dir()}/tpl/msg.tftpl"]

    dependency "src" {
      config_path  = unit.src.path
      mock_outputs = { content = "mock" }
    }

    inputs = {
      content = templatefile(
        "${get_terragrunt_dir()}/tpl/msg.tftpl",
        { v = dependency.src.outputs.content },
      )
    }
  }
}
```

Paths should use `get_terragrunt_dir()` so they resolve to absolute paths at generate time. The attribute is optional and backward compatible.
