#### Export logs to OpenTelemetry

Terragrunt now exports its logs as OpenTelemetry log records, next to traces and metrics, when [`TG_TELEMETRY_LOGS_EXPORTER`](/troubleshooting/open-telemetry) is set. The `otel-logs` experiment flag is no longer needed.

- `none` - no log exporting, the default.
- `console` - write log records to the console as JSON.
- `otlpHttp` - export logs to an OpenTelemetry collector over HTTP.
- `otlpGrpc` - export logs to an OpenTelemetry collector over gRPC.

```bash
export TG_TELEMETRY_TRACE_EXPORTER=otlpHttp
export TG_TELEMETRY_LOGS_EXPORTER=otlpHttp
export OTEL_EXPORTER_OTLP_ENDPOINT=https://collector.example.com:4318
terragrunt run --all -- apply
```

The OTLP exporters read the standard `OTEL_EXPORTER_OTLP_*` environment variables, and the `OTEL_BLRP_*` variables tune batching. See [OpenTelemetry](/troubleshooting/open-telemetry#example-collection-of-traces-metrics-and-logs-with-docker-compose) for a Docker Compose example that sends traces to an OpenTelemetry collector and logs to Quickwit.

Changes since the experiment:

- Records logged outside a unit, such as by the run queue or the OpenTofu/Terraform output of a single-unit `run`, now link to the root command span.
- Buffered records are flushed when a run is interrupted, and the flush waits at most 30 seconds.
- A failed trace or metric flush no longer drops buffered log records.
- Record bodies no longer include ANSI color codes.

Commands that set `TG_TELEMETRY_LOGS_EXPORTER` now export logs without the experiment. Commands that leave it unset or set it to `none` behave as before.
