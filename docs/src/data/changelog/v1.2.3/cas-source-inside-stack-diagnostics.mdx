#### `cas-source-inside-stack` warnings point at the source

The [`cas-source-inside-stack`](/reference/strict-controls/active#cas-source-inside-stack) warning named the `unit` or `stack` block and its source in one line:

```text
WARN  stack bar: unit "foo" in terragrunt.stack.hcl sets update_source_with_cas on source "./units/foo" inside the stack directory, so the generated stack also contains a copy of it; move the source out of the stack directory and select the stack with a // subdirectory in its source
```

Terragrunt now renders each warning as a diagnostic that shows the `source` attribute in the stack file:

```text
WARN   Source inside the stack directory
 --> ../catalog/terragrunt.stack.hcl:2:28
  |
2 |   source                 = "./units/foo"
  |                            ^^^^^^^^^^^^^
  |
  = Stack generation copies the directory of this stack file whole, so the
    generated stack contains this unit twice, and `run --all` runs the copy
    too. Move the unit directory out of the directory of this stack file, and
    use `//` in the stack's source to separate the catalog from the stack
    directory.
```

To fix it, move the stack into a subdirectory of the catalog and keep its sources outside that subdirectory. Then use `//` in the stack's source to separate the catalog from the stack directory, e.g. `source = "../catalog//stacks/bar"`.

With the strict control enabled, the error gives the same instruction.
