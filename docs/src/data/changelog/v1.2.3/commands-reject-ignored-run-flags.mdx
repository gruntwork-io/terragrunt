#### Commands reject `run` flags they ignore

`render`, `info print`, `stack generate`, `stack output`, and `aws-provider-patch` accepted every flag of `run` and ignored the ones that only apply to a run. `terragrunt render --all --out-dir plans` wrote no plan files, and `terragrunt stack generate --report-file report.json` wrote no report.

Passing one of those flags is now an error:

```console
$ terragrunt render --all --out-dir plans
ERROR  flag `--out-dir` is not a valid flag for `render`. Did you mean to use `run --out-dir`?
```

Remove the flag from the command. It had no effect.

| Command | Flags it stops accepting |
| --- | --- |
| `render` | `--source-update`, `--no-hooks`, `--no-auto-retry`, `--no-stack-generate`, `--queue-ignore-errors`, `--queue-ignore-dag-order` |
| `info print` | `--no-stack-generate`, `--queue-ignore-errors`, `--queue-ignore-dag-order` |
| `stack generate` | `--fail-fast`, `--no-hooks`, `--no-auto-retry`, `--queue-ignore-errors`, `--queue-ignore-dag-order` |
| `stack output` | `--fail-fast`, `--source-update`, `--no-hooks`, `--no-auto-retry`, `--no-stack-generate`, `--queue-ignore-errors`, `--queue-ignore-dag-order` |
| `aws-provider-patch` | `--no-stack-generate`, `--queue-ignore-errors`, `--queue-ignore-dag-order` |

All five also stop accepting `--out-dir`, `--json-out-dir`, `--graph-root`, `--no-auto-approve`, `--destroy-dependencies-check`, `--no-destroy-dependencies-check`, `--disable-command-validation`, `--summary-disable`, `--summary-per-unit`, `--report-file`, `--report-format`, and `--report-schema-file`. `stack run` stops accepting `--graph-root`, and keeps every other flag of `run`. `aws-provider-patch` also rejects flags that no command defines, which it accepted and dropped.

The flags that select units, such as `--queue-exclude-dir` and `--queue-include-dir`, still work on every one of these commands.

The environment variables for these flags, such as `TG_OUT_DIR`, can stay set. A command reads only the variables of the flags it accepts.
