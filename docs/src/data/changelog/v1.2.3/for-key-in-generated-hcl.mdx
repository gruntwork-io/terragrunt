#### Generated HCL quotes object keys named `for`

A map with a key named `for` in the `values` of a [`unit`](/reference/hcl/blocks/unit/) or `stack` block made [`terragrunt stack generate`](/reference/cli/commands/stack/generate) write a `terragrunt.values.hcl` file that Terragrunt could not read:

```hcl
m = {
  for  = "x"
  zone = "y"
}
```

```text
Invalid 'for' expression; For expression requires variable name after 'for'.
```

Terragrunt now writes the key as `"for"` in:

- `terragrunt.values.hcl` and `terragrunt.autoinclude.hcl` files written by `terragrunt stack generate`, `terragrunt scaffold` and `terragrunt catalog`
- the output of `terragrunt render --format hcl` and `terragrunt stack output`
- the backend file generated from a `remote_state` block
- attributes overridden by `terragrunt aws-provider-patch`

`terragrunt.auto.tfvars`, written by the `variables-block` experiment, quoted every object key (`"team" = "platform"`). It now quotes only `for` and writes `team = "platform"`.

`terragrunt stack generate` returns an error naming a top-level `values` key that is not a valid identifier, e.g. `"a b"`. It used to write a `terragrunt.values.hcl` file that could not be parsed.
