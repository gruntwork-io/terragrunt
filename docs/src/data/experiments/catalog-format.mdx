Non-interactive output formats for the `catalog` command.

### `catalog-format` - What it does

This experiment flag is no longer needed, as the `catalog` command now accepts a `--format` flag by default. It writes what the catalog discovers to standard output in place of the terminal user interface: `jsonl` emits one JSON object per catalog entry, and `md` emits a Markdown document.

```bash
terragrunt catalog --format=jsonl | jq -c '{kind, title, component_source}'
terragrunt catalog --format=md > catalog.md
```

Both formats render progressively, as entries are discovered, so a consumer that only needs the first few can stop reading before discovery finishes. Entries appear in discovery order, which is not stable between runs.

The `jsonl` records follow a published JSON schema, so consumers can validate what they read.

Without `--format`, the command opens the terminal user interface when standard input and standard output are both terminals, and writes `jsonl` otherwise. Scaffolding a module and copying a unit or stack stay in the terminal user interface.

See [Non-interactive catalog](/features/catalog/non-interactive) for each format and the structure of an entry.

### `catalog-format` - How to provide feedback

Now that the `catalog-format` experiment is complete, please provide feedback in the form of standard [GitHub issues](https://github.com/gruntwork-io/terragrunt/issues).

### `catalog-format` - Criteria for stabilization

Criteria for moving `catalog-format` to a stable release:

- [x] A `--format` flag on `catalog` accepting `jsonl` and `md`.
- [x] Progressive rendering of both formats, so output is usable before discovery completes.
- [x] A published JSON schema for `jsonl` records.
- [x] A default format derived from what the output stream supports, so piping `catalog` does not require passing `--format`.
- [x] Documentation covering each format and the stability guarantees of the record structure.
- [x] Integration test coverage for each format.
- [x] Community feedback on real-world usage.
