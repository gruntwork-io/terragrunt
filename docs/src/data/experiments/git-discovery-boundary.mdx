Limit discovery for [Git-based filter expressions](/features/filter/git), such as `[main...HEAD]`, to the discovery boundary. The experiment also accepts a dependent-side boundary inside the working directory.

### `git-discovery-boundary` - What it does

A Git expression compares two worktrees, and each one is a full checkout of the repository. Without this experiment, Terragrunt discovers units in every directory of both worktrees and ignores the boundary. Some monorepos keep a catalog of unit and stack templates next to the live infrastructure. There, a diff that changes a file the live tree reads makes Terragrunt parse every catalog unit. A catalog unit that only parses after it is generated into a stack then fails the run. One example is a unit that calls `find_in_parent_folders()` for a file that only exists beside the live stack.

With the experiment enabled, two things change:

- Worktree discovery walks only the boundary. The boundary is the inline `(dir)` operand, or [`--discovery-boundary`](/reference/cli/commands/find#discovery-boundary) for a filter without one. If the boundary contains the working directory, the walk covers the working directory instead. Terragrunt does not discover a changed unit outside that directory, even when the unit is the target of the expression.
- A dependent-side boundary can be a directory inside the working directory. Terragrunt starts the search for dependents at the boundary instead of returning an error, so you can run the command from the repository root.

```bash
# From the repository root, plan the changes under ./live and their dependents under ./live
terragrunt stack run plan --experiment git-discovery-boundary --filter '(./live/)...[main...HEAD]'
```

Each worktree mirrors the repository root, so Terragrunt maps the directory into each worktree by its path from the repository root. Worktree discovery stays unbounded when any positive filter has no boundary and `--discovery-boundary` is not set, or when the boundaries are in separate directories.

Stack generation respects the boundary without this experiment, both in the working directory and in Git worktrees.

### `git-discovery-boundary` - How to enable it

```bash
# Via CLI flag
terragrunt stack run plan --experiment git-discovery-boundary --filter '(./live/)...[main...HEAD]'

# Via environment variable
export TG_EXPERIMENT=git-discovery-boundary
terragrunt stack run plan --filter '(./live/)...[main...HEAD]'
```

### `git-discovery-boundary` - How to provide feedback

Share feedback in [Terragrunt GitHub Discussions](https://github.com/gruntwork-io/terragrunt/discussions) or open an issue. Include the filter you ran, the directory you ran it from, and where your repository keeps live infrastructure and catalogs.

### `git-discovery-boundary` - Criteria for stabilization

To move `git-discovery-boundary` to a stable release, the following must be addressed, at a minimum:

- [x] Worktree discovery for Git expressions stays inside the discovery boundary.
- [x] A dependent-side boundary inside the working directory starts the search for dependents there.
- [ ] Decide whether a changed unit outside the boundary should remain a target of the Git expression.
- [ ] Positive feedback from users who run Git-based filters in monorepos with catalogs next to live infrastructure.
