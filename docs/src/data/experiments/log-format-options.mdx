Support for log format options that earlier Terragrunt versions reject, starting with the `minimal` value of the `path` option of the [`%prefix`](/reference/logging/formatting#options) placeholder.

This experiment is ongoing and disabled by default. A [`--log-custom-format`](/reference/logging/formatting) that uses one of these options returns an error unless the experiment is enabled.

### `log-format-options` - What it does

Units generated by nested stacks live deep inside `.terragrunt-stack` directories, so the default `%prefix` repeats a long path on every log line:

```
STDOUT [.terragrunt-stack/app-a/.terragrunt-stack/db] tofu: OpenTofu has been successfully initialized!
```

With this experiment enabled, `%prefix(path=minimal)` shows only the last element of the unit path. When several units in the run share a last element, it adds parent directories until each label is unique. `.terragrunt-stack` counts as a normal path element:

```bash
terragrunt run --all --experiment log-format-options \
  --log-custom-format "%level %prefix(path=minimal,prefix='[',suffix='] ')%msg" -- init
```

```
STDOUT [vpc] tofu: OpenTofu has been successfully initialized!
STDOUT [app-a/.terragrunt-stack/db] tofu: OpenTofu has been successfully initialized!
STDOUT [app-b/.terragrunt-stack/db] tofu: OpenTofu has been successfully initialized!
```

The labels are computed from all units discovered for the run before any unit runs.

### `log-format-options` - How to provide feedback

Provide your feedback on the [GitHub issue that proposed the `minimal` path mode](https://github.com/gruntwork-io/terragrunt/issues/7160).

### `log-format-options` - Criteria for stabilization

To transition the `log-format-options` feature to a stable release, the following must be addressed:

- [ ] Positive feedback from users running nested stacks with `%prefix(path=minimal)`.
- [ ] Decide how `minimal` labels units in runs with git-based filters, where unit paths are relative to a worktree.
