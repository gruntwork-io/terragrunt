Deduplication of the files produced by `generate` blocks through content-addressable storage, with a `mutable` attribute to opt out.

### `mutable-generate` - What it does

This experiment flag is no longer needed, as Terragrunt stores the contents a
`generate` block produces in the [CAS](/features/caching/cas) by default. The
file written at `path` is a read-only link to that stored copy. The link is
read-only because the stored copy is shared: an edit through one path would
change what every later reader of that content sees.

Because the stored copy is addressed by the hash of its contents, anything
generating identical contents links to the same copy instead of writing its own.
A `generate` block declared in a parent configuration writes the same content
into every unit that includes it, so a provider block shared across a few
hundred units is stored once.

The `generate` block accepts a `mutable` attribute for cases where a shared
read-only file does not work:

```hcl
generate "provider" {
  path      = "provider.tf"
  if_exists = "overwrite"
  mutable   = true
  contents  = <<EOF
provider "aws" {
  region = "us-east-1"
}
EOF
}
```

`mutable = true` gives the block a writable file of its own. Use it when
something writes to the generated file, such as a hook that patches it before
`tofu`/`terraform` runs. Terragrunt regenerates the file on every run, and
`tofu`/`terraform` only read it, so most `generate` blocks do not need it.

`--no-cas` writes generated files directly, and `mutable` has no effect. The
backend file generated by a `remote_state` block is always written directly.

See the [`generate` block reference](/reference/hcl/blocks#generate) for every attribute the block accepts.

### `mutable-generate` - How to provide feedback

Now that the `mutable-generate` experiment is complete, please provide feedback in the form of standard [GitHub issues](https://github.com/gruntwork-io/terragrunt/issues).

### `mutable-generate` - Criteria for stabilization

Criteria for moving `mutable-generate` to a stable release:

- [x] A `mutable` attribute on the `generate` block, parsed from both the block and attribute forms.
- [x] Deduplication of non-mutable generated files through the CAS store, materialized as read-only hard links.
- [ ] Confirmation that read-only generated files break no established workflow, including hooks and IaC engines.
- [x] `remote_state.generate` stays out of the CAS and writes its backend file directly into each unit.
- [x] Community feedback on the disk savings actually observed at scale.
