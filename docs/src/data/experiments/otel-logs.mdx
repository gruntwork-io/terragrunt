Export Terragrunt's logs as an OpenTelemetry logs signal.

### `otel-logs` - What it does

This experiment flag is no longer needed. Terragrunt exports its logs as OpenTelemetry log records, next to traces and metrics, when `TG_TELEMETRY_LOGS_EXPORTER` is set:

- `none` - no log exporting (the default).
- `console` - write log records to the console as JSON.
- `otlpHttp` - export logs to an OpenTelemetry collector over HTTP.
- `otlpGrpc` - export logs to an OpenTelemetry collector over gRPC.

The OTLP exporters read the endpoint, headers, and TLS settings from the standard `OTEL_EXPORTER_OTLP_*` environment variables. Set `TG_TELEMETRY_LOGS_EXPORTER_INSECURE_ENDPOINT=true` to turn off TLS for a local collector.

```bash
TG_TELEMETRY_LOGS_EXPORTER=otlpHttp terragrunt run --all -- apply
```

Each record carries the trace and span IDs of the span it was logged in, so a unit's logs link to its span in the backend. Records logged outside a unit, such as by the run queue, link to the root command span.

See [OpenTelemetry](/troubleshooting/open-telemetry) for all settings and a local collector example.

### `otel-logs` - How to provide feedback

Now that the `otel-logs` experiment is complete, please provide feedback in the form of standard [GitHub issues](https://github.com/gruntwork-io/terragrunt/issues).

### `otel-logs` - Criteria for stabilization

To transition the `otel-logs` feature to a stable release, the following must be addressed:

- [x] Confirm the exporter types and configuration cover common collector setups.
- [x] Validate log volume and batching behavior on large stacks.
- [x] Confirm trace/span correlation is reliable across the run lifecycle, including run-level logs emitted outside a unit span.
- [x] Settle on the dependency stability story for the OpenTelemetry logs SDK, which is still pre-1.0.
