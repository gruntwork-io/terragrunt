Shows progress for slow Terragrunt operations, so a long wait does not look like a hang.

### `slow-task-reporting` - What it does

Terragrunt reports an operation once it has run for 100ms. These operations are reported:

- Source downloads, and waits for the lock on the download directory or on the shared Git store
- Git worktree creation and Git reference comparison for `--filter` with Git references
- Unit discovery for `run --all`, `find` and `list`
- `dependency` output fetches
- Provider caching
- Waits for a new S3 bucket, DynamoDB table or GCS bucket to become ready
- Unit and stack source fetches during `stack generate`
- Catalog repository clones in `terragrunt catalog`

On a terminal, Terragrunt draws one progress line. It shows the operation, how long it has run, and how many other operations are running:

```text
| Downloading source from git::https://github.com/acme/modules.git?ref=v1.2.0... (12s) +2 more
```

The line fits the terminal width and is redrawn when the terminal is resized. Log lines appear above it. When the operation succeeds, an INFO log line with the elapsed time replaces it. In a `run --all`, all units share the line. It shows the operation that has run the longest and counts the others.

Everywhere else, Terragrunt writes INFO log lines. It logs one when the operation starts or reaches 100ms, one every 30 seconds while it runs, and one when it succeeds. The 30-second line stops CI systems from ending a job that looks silent.

```text
INFO   Fetching outputs of dependency ../vpc...
INFO   Fetching outputs of dependency ../vpc... (30s elapsed)
INFO   Fetched outputs of dependency ../vpc (41.7s)
```

Terragrunt writes log lines instead of the progress line when any of these is true:

- Standard error is not a terminal, or the terminal is narrower than 20 columns.
- `TERM` is unset or `dumb`. Windows does not need `TERM`, but its console must support ANSI escape sequences.
- A CI environment is detected through `CI`, `TF_BUILD`, `TEAMCITY_VERSION`, `JENKINS_URL` or `TF_IN_AUTOMATION`.
- Logs use the `json` format, logging is disabled, or the log level is `warn` or higher.

To get log lines on a terminal, set `TERM=dumb` or `CI=true`. `terragrunt catalog` always writes log lines, because its TUI owns the terminal.

With `--log-level warn` or higher, or with `--log-disable`, nothing is reported, not even the 30-second lines.

The animation uses Unicode characters on terminals with a UTF-8 locale and in Windows Terminal. Other terminals get `|`, `/`, `-` and `\`.

```bash
terragrunt run --all --experiment slow-task-reporting -- plan
```

### `slow-task-reporting` - How to provide feedback

Provide your feedback on the [`slow-task-reporting` GitHub Discussion](https://github.com/gruntwork-io/terragrunt/discussions/6226).

### `slow-task-reporting` - Criteria for stabilization

To transition the `slow-task-reporting` feature to a stable release, the following must be addressed:

- [x] Validate the progress line across common terminal emulators (iTerm2, Terminal.app, Windows Terminal, the Windows console, GNOME Terminal)
- [x] Extend progress reporting to additional slow operations (e.g., provider caching)
- [ ] Community feedback on usefulness and threshold tuning
- [x] Ensure no interference with structured log output when using `--log-format json`
- [x] Ensure no interference with the output of units that run concurrently, or with the catalog TUI
