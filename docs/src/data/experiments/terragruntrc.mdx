Read defaults for environment variables and CLI flags from a `.terragruntrc` file that can be committed to a repository.

### `terragruntrc` - What it does

Terragrunt is configured through flags and environment variables, and neither can be committed alongside the code they configure. Teams work around that with a README that asks every engineer to export the same variables, a Makefile, or a shell wrapper. When the recommended settings change, the exports quietly go stale.

When this experiment is enabled, Terragrunt looks for a `.terragruntrc.json`, `.terragruntrc.yaml` or `.terragruntrc.yml` file before it parses the command line, and uses it to supply defaults:

```json
{
  "env": {
    "TG_PROVIDER_CACHE": "1",
    "TF_CLI_CONFIG_FILE": "./terraformrc.hcl"
  },
  "flags": [
    { "name": "non-interactive", "default": true }
  ],
  "commands": [
    { "name": "run", "flags": [{ "name": "parallelism", "default": 8 }] }
  ]
}
```

The same file in YAML:

```yaml
env:
  TG_PROVIDER_CACHE: "1"
  TF_CLI_CONFIG_FILE: ./terraformrc.hcl
flags:
  - name: non-interactive
    default: true
commands:
  - name: run
    flags:
      - name: parallelism
        default: 8
```

Because the file is read before anything else, the variables in `env` are in place before the provider cache server starts, which is not true of variables set through `extra_arguments`.

Anything given on the command line, and anything already exported in the shell, still wins over the file. See [the reference page](/reference/terragruntrc) for discovery order, precedence and value handling.

### `terragruntrc` - How to provide feedback

Share your experience in [#3572](https://github.com/gruntwork-io/terragrunt/issues/3572), especially:

- Which settings you ended up committing, and at which level of the repository.
- Whether per-command defaults are expressive enough, or whether you need them scoped further.
- Whether first-file-wins discovery is what you expected, or whether you want files to merge.

### `terragruntrc` - Criteria for stabilization

- The schema has held up against real repositories without needing a breaking change.
- Discovery and precedence are unsurprising to users who did not write the file.
- The interaction with flags that are read before the command line is fully parsed is settled.
