---
name: dependency-fetch-output-from-state
description: |
  Fetch dependency outputs directly from the state file instead of using `tofu output`.
type: bool
env:
  - TG_DEPENDENCY_FETCH_OUTPUT_FROM_STATE
---

import { Aside } from '@astrojs/starlight/components';
import Before from '@components/Before.astro';
import Since from '@components/Since.astro';

This flag modifies how Terragrunt retrieves output values from dependent units. When enabled, Terragrunt will read the outputs directly from the state file instead of running `tofu output` or `terraform output`.

<Aside type="note">
This flag is equivalent to enabling the `dependency-fetch-output-from-state` experiment. You can also enable this feature using `--experiment dependency-fetch-output-from-state` or `--experiment-mode`. For more information, see the [Experiments documentation](/reference/experiments/active#dependency-fetch-output-from-state).
</Aside>

The main benefit this flag provides is performance. Reading directly from state is typically faster than executing the OpenTofu/Terraform binary to get the same outputs.

<Before version="1.1.5">
Outside `render` and `render-json`, a network, permissions, or parsing failure from a direct state read ends the run instead of retrying through OpenTofu/Terraform. A missing state object still follows the dependency block's `mock_outputs` behavior.
</Before>

<Since version="1.1.5">
Outside `render` and `render-json`, Terragrunt retries a failed direct state read with `tofu output` or `terraform output`, unless the state object is missing. If native output retrieval succeeds, only the direct-read speedup is lost. For missing outputs, configured `mock_outputs` are used when outputs are unavailable, while `skip_outputs` forces mocks. The render commands keep that same behavior.
</Since>

<Before version="1.1.4">
This approach is only supported by the S3 backend.
</Before>

<Since version="1.1.4">
This approach supports S3 and GCS backends. It also supports the Azure Storage (`azurerm`) backend when the [`azure-backend`](/reference/experiments/active#azure-backend) experiment is enabled. Other backends continue to use `tofu output` or `terraform output`.

Terragrunt also uses the native output path for Azure state protected by `customer_provided_key`, Azure configurations requiring native-only authentication or endpoint behavior, and GCS configurations whose backend-specific credential or endpoint behavior is not yet mirrored by the direct reader.
</Since>

<Aside type="caution">
<Before version="1.1.5">
This flag is **not compatible with OpenTofu state encryption**. The encrypted envelope carries no plaintext `outputs` object, so Terragrunt treats the dependency as having no outputs. Referencing a missing output can then fail with `Unsupported attribute`, while configured mock-output merging can supply a mock value instead. Disable this flag with `--no-dependency-fetch-output-from-state` to force native output retrieval.
</Before>

<Since version="1.1.5">
The direct reader does not evaluate OpenTofu's encryption configuration or key providers from the `remote_state.encryption` map. Outside `render` and `render-json`, Terragrunt recognizes the encrypted envelope and retries with `tofu output` or `terraform output`, where the configured OpenTofu/Terraform binary performs decryption. If native output retrieval succeeds, only the speedup is lost. For missing outputs, configured `mock_outputs` are used when outputs are unavailable, while `skip_outputs` forces mocks. The render commands keep that same behavior. Use `--no-dependency-fetch-output-from-state` when a render command must resolve real outputs from encrypted state.
</Since>
</Aside>

<Aside type="caution">
OpenTofu/Terraform may change the state schema. Pin the OpenTofu/Terraform version when using this flag because compatible-looking schema changes can affect direct-read results.
</Aside>

<Aside type="tip">
Direct output fetching is a performance optimization. For more details on performance optimizations, their tradeoffs, and other performance tips, read the dedicated [Performance documentation](/troubleshooting/performance).
</Aside>
