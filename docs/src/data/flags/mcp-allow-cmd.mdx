---
name: allow-cmd
description: |
  Allow MCP tools to run a command a configuration names, such as one a run_cmd or a hook calls, given as a pattern like 'jq **'. Repeatable. Requires --allow=exec.
type: list(string)
env:
  - TG_ALLOW_CMD

<Aside type="tip" title="Experimental">
This flag is gated behind the [`mcp-command`](/reference/experiments/active#mcp-command) experiment. Enable it with `--experiment=mcp-command` or `TG_EXPERIMENT=mcp-command`.
</Aside>

[`--allow=exec`](/reference/cli/commands/mcp#allow) runs `tofu`, `terraform`, and `git`, and refuses every other program a configuration names. This flag allows more, one pattern at a time:

```bash
terragrunt mcp --allow=exec --allow-cmd 'git rev-parse --show-toplevel' --allow-cmd 'jq **'
```

A pattern is split into words the way `--auth-provider-cmd` is, so quoting works as it does in a shell. Quote the whole pattern as well, so your own shell passes it through as one value.

- The first word names the program and cannot contain glob syntax. A bare name, e.g. `jq`, matches a configuration that calls `jq`, or that calls the path where the server's `PATH` finds `jq`. A path, e.g. `./scripts/version.sh`, matches a configuration that calls the same path once `.` and `..` are resolved on both sides, so `scripts/version.sh` matches too. A bare name does not match a file the tree ships, so `git **` does not allow `./git`.
- Each later word matches one argument. Glob syntax applies within that argument, e.g. `--profile=*`.
- A word that is `**` matches any number of arguments, none included.

| Pattern | Allows | Refuses |
| --- | --- | --- |
| `git rev-parse --show-toplevel` | `git rev-parse --show-toplevel` | `git rev-parse --show-toplevel --quiet` |
| `jq *` | `jq .` | `jq -r .version` |
| `jq **` | `jq`, `jq -r .version version.json` | `yq .` |
| `aws ** --profile=*` | `aws sts get-caller-identity --profile=dev` | `aws sts get-caller-identity` |
| `./scripts/version.sh **` | `scripts/version.sh --short` | `version.sh` |

An argument containing spaces stays one word, so `sh -c 'echo hello'` allows `run_cmd("sh", "-c", "echo hello")` and nothing else. A pattern that cannot be parsed, or that contains a shell operator such as `;` or `|`, is refused at startup.

## Finding out what to allow

You do not have to guess. Call a tool once and read the `degraded` list, which names every command that was refused:

```json
"degraded": [
  "stubbed \"jq -r .version\": --allow=exec runs Terragrunt's own commands, not programs a configuration names"
]
```

If your MCP client supports elicitation (the protocol's way for a server to ask the client's user a question), the server offers the refused programs for approval instead, and you can decide per call rather than up front. An approval covers the program as the configuration called it, by name or by path, with any arguments, for that call. This flag is the answer once you know which commands a tree needs and are tired of approving them.

<Aside type="caution" title="Allowing is not scoping">
An allowed command runs with the credentials and filesystem access this server process has. A pattern bounds the arguments a command runs with, not what the program does with them, so `sh -c **` allows any code a configuration likes. A relative path allows whatever file the repository puts at that path, and the agent chooses the repository. Prefer patterns that pin the arguments a configuration actually passes.
</Aside>
