name: inputs

type: map(any)
examples:
  - code: |
      # terragrunt.hcl

      inputs = {
        string      = "string"
        number      = 42
        bool        = true
        list_string = ["a", "b", "c"]
        list_number = [1, 2, 3]
        list_bool   = [true, false]

        map_string = {
          foo = "bar"
        }

        map_number = {
          foo = 42
          bar = 12345
        }

        map_bool = {
          foo = true
          bar = false
          baz = true
        }

        object = {
          str  = "string"
          num  = 42
          list = [1, 2, 3]

          map = {
            foo = "bar"
          }
        }

        from_env = get_env("FROM_ENV", "default")
      }

The `inputs` attribute is a map of the input variables and values to pass to OpenTofu/Terraform. Each entry reaches OpenTofu/Terraform through [the environment variable mechanism](https://opentofu.org/docs/language/values/variables/#environment-variables), in the form `TF_VAR_variablename`, with the value encoded as JSON.

Because the values pass through environment variables and JSON, the type information is lost when crossing the boundary between Terragrunt and OpenTofu/Terraform. You must specify the proper [type constraint](https://opentofu.org/docs/language/values/variables/#type-constraints) on the variable in OpenTofu/Terraform for it to process the input as the right type.

The type constraint also decides how the value is read. A variable declared as `string`, or declared with no type at all, receives the value verbatim. Every other type constraint makes OpenTofu/Terraform read the value as an HCL expression, where `${...}` means interpolation. Terragrunt escapes those sequences for you when the module reads a value as HCL, so text like `${just_a_string}` reaches the module as written.

<Since version="v1.2.2">

A unit with many or large inputs can exceed the operating system's limit on the size of a process environment. The [`variables-block`](/reference/experiments/active#variables-block) experiment adds a [`variables`](/reference/hcl/blocks#variables) block that can write inputs to an auto-loaded variables file.

</Since>

Using this attribute is roughly equivalent to setting the corresponding `TF_VAR_` environment variable. For example, setting this in your `terragrunt.hcl`:

```hcl
# terragrunt.hcl
inputs = {
  instance_type  = "t2.micro"
  instance_count = 10

  tags = {
    Name = "example-app"
  }
}
```

And running:

```bash
terragrunt apply
```

This is roughly equivalent to running:

```bash
TF_VAR_instance_type="t2.micro" \
TF_VAR_instance_count=10 \
TF_VAR_tags='{"Name":"example-app"}' \
tofu apply # or terraform apply
```

### Variable precedence

Variables loaded in OpenTofu/Terraform use the following precedence order, with the highest precedence being lowest on the list:

1. `inputs` set in `terragrunt.hcl` files.
2. Explicitly set `TF_VAR_` environment variables (these override the `inputs` set in `terragrunt.hcl` if they conflict).
3. `terraform.tfvars` files if present.
4. `terraform.tfvars.json` files if present.
5. Any `*.auto.tfvars` or `*.auto.tfvars.json` files, processed in lexical order of their filenames.
6. Any `-var` and `-var-file` options on the command line, in the order they are provided.
