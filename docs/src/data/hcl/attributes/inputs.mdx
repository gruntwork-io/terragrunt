The `inputs` attribute sets a module's variables. Each key sets the variable of the same name.

<FileTree>

- live
  - app
    - **terragrunt.hcl** sets the inputs
- modules
  - app
    - main.tf
    - **variables.tf** declares the variables

</FileTree>

<SideBySide>

```hcl title="modules/app/variables.tf" "instance_type" "instance_count" "tags"
variable "instance_type" {
  type = string
}

variable "instance_count" {
  type = number
}

variable "tags" {
  type = map(string)
}
```

```hcl title="live/app/terragrunt.hcl" "instance_type" "instance_count" "tags"
terraform {
  source = "../..//modules/app"
}

inputs = {
  instance_type  = "t2.micro"
  instance_count = 10
  tags = {
    Name = "example-app"
  }
}
```

</SideBySide>

Terragrunt passes each input to OpenTofu/Terraform as a [`TF_VAR_` environment variable](https://opentofu.org/docs/language/values/variables/#environment-variables), with the value encoded as JSON. Running `terragrunt apply` in `live/app` is roughly equivalent to running:

```bash
TF_VAR_instance_type="t2.micro" \
TF_VAR_instance_count=10 \
TF_VAR_tags='{"Name":"example-app"}' \
tofu apply # or terraform apply
```

<Aside type="caution" title="Declare a type on each variable">

Environment variables are strings, so OpenTofu/Terraform uses a variable's [type constraint](https://opentofu.org/docs/language/values/variables/#type-constraints) to read the value. A variable with no type receives a list or map as a JSON string.

</Aside>

A `null` input reaches the module as `null`, which overrides the variable's default. A literal `${...}` in a value reaches the module as written.

<Since version="v1.2.2">

A unit with many or large inputs can exceed the operating system's limit on the size of a process environment. The [`variables-block`](/reference/experiments/active#variables-block) experiment adds a [`variables`](/reference/hcl/blocks#variables) block that can write inputs to an auto-loaded variables file.

</Since>

### Variable precedence

OpenTofu/Terraform uses the first of these that sets a variable:

1. `-var` and `-var-file` options on the command line. If several set it, the last one wins.
2. `*.auto.tfvars` and `*.auto.tfvars.json` files. If several set it, the last filename in lexical order wins.
3. A `terraform.tfvars.json` file.
4. A `terraform.tfvars` file.
5. A `TF_VAR_` environment variable you set yourself.
6. `inputs`.

By default, a unit's `inputs` merge with those of the files it includes, key by key. The unit's value wins for a key set in both.
