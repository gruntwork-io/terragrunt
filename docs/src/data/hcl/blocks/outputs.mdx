<Aside type="tip" title="Experimental">
  The `outputs` block needs the [`outputs-block`](/reference/experiments/active#outputs-block) experiment. Enable it with `--experiment outputs-block` or `TG_EXPERIMENT=outputs-block`. Without the experiment, a config that has the block fails with an error.
</Aside>

The `outputs` block lists the outputs of a unit. Each output can have a mock value. Units that depend on this unit read the mock values until it has real outputs, e.g. before its first apply.

You declare the mock values once, in the unit that produces the outputs. Its dependents need no `mock_outputs` in their [`dependency`](/reference/hcl/blocks#dependency) blocks.

Dependents read the mock values while the unit has no state yet or its state has no outputs. The rules are the same as for `mock_outputs`. Any other error while reading the state fails the run.

The block goes in a unit's `terragrunt.hcl`. A stack file does not accept it. A [`variables`](/reference/hcl/blocks#variables) block can read the declared outputs too, the same way `inputs` does.

### With a dependency block

Settings on a `dependency` block override the `outputs` block of the unit it reads:

- `mock_outputs` overrides `mock_value` one key at a time. A key that `mock_outputs` leaves out keeps its declared mock value.
- `mock_outputs_allowed_terraform_commands` and `mock_outputs_merge_strategy_with_state` override `mock_strategy` when set.

When the unit has outputs in state, every declared output has to be among them. A missing one is an error, unless `merge_with_state` fills it from `mock_value`. The `render` command does not raise this error.

`render` prints the `dependency` block as you wrote it. The declared mock values appear in the resolved `inputs`.

A `dependency` block whose `config_path` points at a stack reads no `outputs` block.

When a `dependency` block reads a unit without an `outputs` block, Terragrunt prints the `outputs-block` tip once per run. Turn it off with `--no-tip outputs-block`.

### Through include

An included file can declare the `outputs` block. With a `shallow` merge, the unit's own `outputs` block replaces the included one. With a `deep` merge, Terragrunt combines the two blocks by output name. When both declare the same output, the unit's declaration wins.

### Checking outputs with hcl validate

[`terragrunt hcl validate --outputs`](/reference/cli/commands/hcl/validate#outputs) runs two checks:

- Every declared output exists in the OpenTofu/Terraform module the unit runs.
- Every `dependency.<name>.outputs.<output>` reference names an output that the dependency declares. The check skips a dependency that has no `outputs` block.

Without the flag, `hcl validate` runs neither check.

```bash
terragrunt hcl validate --outputs --experiment outputs-block
```

For the first check, Terragrunt reads the module the way a run does. It downloads the unit's `terraform.source` and adds the files your `generate` blocks produce, without writing them to disk. It runs no hooks, so it does not see a file that a hook writes.

Terragrunt reads the module files as the unit's OpenTofu/Terraform binary does. With OpenTofu, a `.tofu` file replaces the `.tf` file of the same name. With Terraform, it ignores `.tofu` files.

The second check covers the unit file, the files it includes, and its autoinclude file. Each error points at the file that has the reference. When the autoinclude file overrides a `dependency` block, the check uses the overriding block.

The check accepts both forms of a reference, so it treats `dependency["vpc"].outputs["vpc_id"]` like `dependency.vpc.outputs.vpc_id`. It checks a reference to one instance of an expanded dependency, e.g. `dependency.vpc["primary"].outputs.vpc_id`, against that instance.

Neither check runs on a unit written as `terragrunt.hcl.json`. The second check skips an include with `merge_strategy = "no_merge"` and without `expose = true`. It also skips a reference whose instance key or output name is computed, e.g. `dependency.vpc.outputs[local.name]`.
