<Aside type="tip" title="Experimental">
  The `outputs` block is gated behind the `outputs-block` experiment. Enable it with `--experiment outputs-block` (or `TG_EXPERIMENT=outputs-block`) until it graduates to general availability. Declaring the block without the experiment enabled returns an error. See the [experiment documentation](/reference/experiments/active#outputs-block).
</Aside>

The `outputs` block declares the outputs a unit emits. It belongs in a unit's `terragrunt.hcl`; a stack file does not accept it. Each output can set a mock value that dependents read while the unit has no state yet or its state holds no outputs, e.g. before its first apply, under the rules of `mock_outputs` on a [`dependency`](/reference/hcl/blocks#dependency) block: any other failure to read the state is an error. A `mock_strategy` block says when dependents may read the mocks.

A [`variables`](/reference/hcl/blocks#variables) block reads the declared outputs the same way a dependent's `inputs` do.

### With a dependency block

A `dependency` block and the `outputs` block of the unit it reads combine as follows:

- `mock_outputs` on the `dependency` block wins over `mock_value` key by key. A key the `dependency` block leaves out keeps the declared mock value.
- `mock_outputs_allowed_terraform_commands` and `mock_outputs_merge_strategy_with_state` on the `dependency` block win over `mock_strategy` when set.
- When the state of the unit is read, every declared output has to be in it. A declared output that is missing is an error, unless `merge_with_state` fills it from `mock_value`. The `render` command tolerates the gap.
- A `dependency` block whose `config_path` points at a stack reads no `outputs` block.
- `render` shows the `dependency` block as written; the declared mock values appear in the resolved `inputs`.

When a `dependency` block reads a unit that declares no `outputs` block, Terragrunt gives the `outputs-block` tip once per run. Disable it with `--no-tip outputs-block`.

### Through include

The block is merged through `include` like the `errors` block: a `shallow` merge takes the including unit's block whole, and a `deep` merge combines the declarations by output name, with the unit's declarations winning.

### Checking the contracts

[`terragrunt hcl validate --outputs`](/reference/cli/commands/hcl/validate#outputs) checks the contracts: every declared output has to exist in the OpenTofu/Terraform module the unit runs, and every `dependency.<name>.outputs.<output>` reference has to name an output the dependency declares, when it declares any. Without the flag, `hcl validate` runs neither check.

```bash
terragrunt hcl validate --outputs --experiment outputs-block
```

For the first check, Terragrunt fetches the `terraform.source` of the unit into the download directory, as a run does and without running any hook, and evaluates its `generate` blocks against an in-memory copy of the module files, so it writes no generated file into the module directory. A unit without a `source` is viewed as the run copies it into the cache directory, so a file `exclude_from_copy` leaves out is not seen, unless the unit runs in place. The module files are read as the OpenTofu/Terraform binary of the run reads them, `terraform_binary` included: with OpenTofu, a `.tofu` file hides the `.tf` file of the same name, with Terraform, `.tofu` files are not read, and a file whose name starts with a dot is never read. When Terragrunt cannot ask the binary which one it is, it reads every module file. A file a hook writes during a run is not seen. With `--inputs`, the check reads the module that mode prepares on disk.

For the second check, Terragrunt reads the unit file, the files it merges or exposes through `include`, and its autoinclude file, and reports each reference in the file that holds it. References resolve against the unit's merged `dependency` blocks, so a dependency the autoinclude file overrides is checked as that file declares it, and a `dependency` block of the unit file that the autoinclude file replaces is not read.

- An include with `merge_strategy = "no_merge"` that is not exposed is never evaluated, so it is not checked.
- `hcl validate` does not discover `terragrunt.hcl.json` units, so neither check runs on them.
- Each step of a reference may be an attribute or a literal string index, so `dependency["vpc"].outputs["vpc_id"]` is checked like `dependency.vpc.outputs.vpc_id`.
- A reference to one instance of an expanded dependency, written as `dependency.vpc["primary"].outputs.vpc_id`, `dependency.vpc.primary.outputs.vpc_id`, or `dependency.vpc[0].outputs.vpc_id` for a `count` expansion, is checked against that instance.
- A reference whose instance key or output name is not a literal is not checked.
- Without `--inputs`, a dependency whose unit config cannot be read is reported at the `config_path` that names it, unless the run validates that unit, whose own parse reports what is wrong with it.
