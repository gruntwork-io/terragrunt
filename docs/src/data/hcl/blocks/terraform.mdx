The `terraform` block configures how Terragrunt runs OpenTofu/Terraform: where to get the module, which files to copy into the working directory, extra CLI arguments, and commands to run before and after `tofu`/`terraform`.

```hcl
# terragrunt.hcl

terraform {
  source = "git::https://github.com/acme/modules.git//vpc?ref=v1.0.0"

  extra_arguments "retry_lock" {
    commands  = get_terraform_commands_that_need_locking()
    arguments = ["-lock-timeout=20m"]
  }

  before_hook "fmt" {
    commands = ["apply", "plan"]
    execute  = ["tofu", "fmt", "-check"]
  }
}
```

With a `source`, Terragrunt downloads the module into `.terragrunt-cache`, copies the unit's directory into the same place, and runs `tofu`/`terraform` there. It skips hidden files and directories in the copy unless [`include_in_copy`](/reference/hcl/blocks/terraform#include_in_copy) names them.

### Module sources

A `tfr://` source pulls a module from a module registry, in the form `tfr://REGISTRY_HOST/MODULE_SOURCE[?version=VERSION]`:

```hcl
# terragrunt.hcl

terraform {
  source = "tfr://registry.opentofu.org/terraform-aws-modules/vpc/aws?version=3.3.0"
}
```

- Without `?version=` or a [`version`](/reference/hcl/blocks/terraform#version) attribute, Terragrunt downloads the latest stable version. Pin a version for reproducible runs.
- `tfr:///` with three slashes uses the default registry: `registry.opentofu.org` for OpenTofu, and `registry.terraform.io` for Terraform. When Terragrunt can't tell which one it runs, it uses `registry.opentofu.org`. Set `TG_TF_DEFAULT_REGISTRY_HOST` to use another host.
- `//` selects a submodule, e.g. `tfr:///terraform-aws-modules/iam/aws//modules/iam-policy?version=4.3.0`.
- For a private registry, set `TG_TF_REGISTRY_TOKEN` to an API token for it.

An `oci://` source pulls a module from an OCI registry, in the form `oci://REGISTRY_HOST/REPOSITORY[//SUBDIR][?tag=TAG|?digest=DIGEST]`, e.g. `oci://ghcr.io/acme/terraform-modules/vpc?tag=1.0.0`. Without a `tag` or `digest`, Terragrunt uses the `latest` tag. See [OCI registries](/features/units/oci).

### Version constraints

The [`version`](/reference/hcl/blocks/terraform#version) attribute resolves a `tfr://` source against the registry's list of versions:

- It applies to `tfr://` sources only. Setting it with any other source is an error, and so is also setting `?version=` in the source.
- The `--source` flag and `TG_SOURCE` replace `version` along with `source`. They take an exact `?version=` only, not a constraint.
- Terragrunt checks the registry on every run, so it downloads a newly published version that satisfies the constraint without `--source-update`.
- A prerelease qualifies only when the constraint names one, e.g. `>= 2.0.0-rc1`, as in OpenTofu/Terraform.

### Hook commands

Besides `tofu`/`terraform` commands, a hook's `commands` can name three stages of a Terragrunt run: `terragrunt-read-config`, `init-from-module`, and `init`. Running `terragrunt plan` on a unit with a `source` runs hooks in this order:

```d2
shape: sequence_diagram

terragrunt: Terragrunt
hooks: Hooks
tofu: tofu

terragrunt -> terragrunt: Load terragrunt.hcl
terragrunt -> hooks: 'after_hook "terragrunt-read-config"'

download: "Download source, unless .terragrunt-cache has it" {
  terragrunt -> hooks: 'before_hook "init-from-module"'
  terragrunt -> terragrunt: Download source
  terragrunt -> hooks: 'after_hook "init-from-module"'
}

init: "Auto-Init, when the module needs it" {
  terragrunt -> hooks: 'before_hook "init"'
  terragrunt -> tofu: tofu init
  terragrunt -> hooks: 'after_hook "init"'
}

plan: "The command you ran" {
  terragrunt -> hooks: 'before_hook "plan"'
  terragrunt -> tofu: tofu plan
  terragrunt -> hooks: 'after_hook "plan"'
}
```

When a stage fails, Terragrunt runs that stage's after hooks that set `run_on_error = true`, then its `error_hook` blocks whose `on_errors` match the error. An `error_hook` with `init-from-module` catches download errors.

`terragrunt-read-config` and `init-from-module` hooks run in the unit's directory, and other hooks in the directory Terragrunt runs OpenTofu/Terraform in.

<Aside type="caution" title="Use terragrunt-read-config in an after_hook">

Terragrunt ignores a `before_hook` with `terragrunt-read-config`, and a hook that names `read-config` never runs. Neither is an error.

</Aside>

### A note about using modules from the registry

Terragrunt runs **shared service modules** as **root modules**. OpenTofu/Terraform modules fall into two groups:

- A **root module** is one you run `tofu init` and `tofu apply` in directly. It has the blocks that configure OpenTofu/Terraform, such as `backend` and `provider` blocks.
- A **shared module** is one other modules call through `module` blocks. It lacks those blocks.

Terragrunt splits shared modules in two:

- A **shared service module** deploys on its own once something adds the `backend` and `provider` blocks, e.g. [terraform-aws-modules/vpc](https://registry.terraform.io/modules/terraform-aws-modules/vpc/aws/latest).
- A **shared module** only works composed with other modules or resources, e.g. [consul-security-group-rules](https://registry.terraform.io/modules/hashicorp/consul/aws/latest/submodules/consul-security-group-rules).

Terragrunt generates the missing blocks to run a shared service module as a root module. Most registry modules are shared modules meant for composition, so Terragrunt can't always deploy them. Two limitations block the conversion:

- Every complex variable needs a `type`, or OpenTofu/Terraform reads the input Terragrunt passes as a `string`. This includes lists and maps.
- Derived sensitive outputs must be marked `sensitive`. See [sensitive variables](https://learn.hashicorp.com/tutorials/terraform/sensitive-variables#reference-sensitive-variables).

If a registry module fails to deploy with Terragrunt, [open an issue on the Terragrunt repository](https://github.com/gruntwork-io/terragrunt/issues) with the module and the error message, rather than on the module's repository.
