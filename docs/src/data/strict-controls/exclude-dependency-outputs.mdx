Throw an error when an `exclude` block reads dependency outputs.

### `exclude-dependency-outputs` - Reason

Terragrunt builds the run queue before it reads dependency outputs, so an `exclude` block that reads one can't remove a unit from the `run --all` queue, and its `exclude_dependencies` has no effect:

```hcl
dependency "vpc" {
  config_path = "../vpc"
}

exclude {
  # Not known while Terragrunt builds the run queue.
  if      = dependency.vpc.outputs.skip
  actions = ["all"]
}
```

Terragrunt warns about this by default. Enabling the control turns it into an error that names the file and the attribute:

```text
exclude.if in /path/to/terragrunt.hcl cannot reference dependency outputs under the exclude-dependency-outputs strict control; Terragrunt builds the run queue before it reads them, so set exclude.if from a feature flag instead
```

The error also stops single-unit commands, such as `terragrunt plan`. Without the control, `no_run = true` still skips a unit whose `if` reads a dependency output, because Terragrunt reads the outputs before it runs the unit.

Read a [feature flag](/reference/hcl/blocks#feature) instead:

```hcl
feature "skip" {
  default = false
}

exclude {
  if      = feature.skip.value
  actions = ["all"]
}
```
